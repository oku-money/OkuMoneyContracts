Notes
-----

OracleRelay (98.85% lines / 100% functions / 71.43% branches): the four
uncovered branches are unreachable defensive guards. `feedDecimals > 18` is
rejected at `initialize` / `setPriceFeed`, so the runtime branch in
`getUsdcPrice` is forward-compat dead code. The other three are short-circuit
branches inside the bounds checks that forge-coverage counts separately
(e.g. min<floor vs. max>ceiling inside the same `if`).

LitePSM (76% branches) and OkuDollar (89.8% branches): all uncovered branches
are defensive guards unreachable under the MAX_MULTIPLIER cap or forward-compat
sentinels for code paths blocked by upstream guards. The four LitePSM lines
that show as uncovered are inside the `oracleRelay == address(0)` no-op
branch of `_pegCheck` and the queued-redemption fallback when the buffer
is exactly zero (covered by invariants, not unit tests).

OkuDollar's three uncovered lines are the inherited ERC-20 `_update`'s
`UseWrapInstead` / `UseUnwrapInstead` reverts (only reachable via direct
`_mint` / `_burn`, both forbidden) and the `setNextUsdYieldRate` validation
edge case.

No user-callable code path is uncovered.
